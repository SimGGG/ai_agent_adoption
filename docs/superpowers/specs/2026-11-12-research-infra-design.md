# 연구 수행 환경 설계

**대상 연구**: DML 기반의 AI Agent 도입으로 인한 숙련셋 변화 분석 (`proposal.md`)
**작성일**: 2026-11-12 · **상태**: 저자 검토 대기

이 문서는 `proposal.md`의 분석을 실행하고 논문을 쓰기 위한 작업 환경의 구성을 정한다. 분석 방법 자체는 `proposal.md`가 정하며, 이 문서는 폴더, 자료 처리 흐름, 실행 방식, 작업 규칙만 다룬다.

## 1. 목적과 범위

**만드는 것**

1. 실험 공간과 논문 공간이 나뉜 폴더 구조와 공간별 Claude 작업 규칙
2. 원자료를 분석용 중간 자료로 바꾸는 처리 스크립트
3. `proposal.md` 부록 A의 추정 함수를 옮긴 모듈과 그 시험 코드
4. 자료 점검(S0) 스크립트와 보고서
5. 단계별 실행 스크립트(S1~S12)와 실행 기록 방식
6. 확정된 표와 그림을 논문 공간으로 내보내는 스크립트
7. 논문 원고의 LaTeX 틀

**만들지 않는 것**

- 분석 결과 자체. 실제 추정 실행은 자료 점검 결과로 확정 사항(`proposal.md` 10장)을 정한 뒤의 일이다.
- 특정 학술지의 서식. 투고처가 정해지면 그때 적용한다.
- 논문 본문.

## 3. 자료 현황

수치 옆의 "(표본)"은 연도별 일부 묶음만 읽어 얻은 값이며 자료 점검에서 전체로 다시 계산한다.

### 3.1 공고 자료 (`data/postings/pfile_{연도}.parquet`)

- 2021~2026년 6개 파일, 약 2,000만 건, 68개 열, 7.9GB. 2026년은 수집이 진행 중인 시점의 자료이다.
- 본문이 같은 공고를 전체 기간에 걸쳐 하나로 묶은 중복 제거판이다. `dup_count`가 묶인 건수이다. `proposal.md` 3.5절의 중복 제거 규칙은 이것으로 대체한다.
- 사업체 열(`bzno`, `ksic10`, `firm_emp`)은 공고의 회사명·주소를 고용보험 사업장 정보와 대조해 붙인 값이다. 사업자번호가 있는 공고는 연도별 70~89%이다.
- 사람인 공고는 2025년 이전 제목(`title`)이 비어 있다.
- 숙련 매칭의 표본 정밀도는 1차 매칭 0.58~0.61, 2차 매칭 0.40이다(명세서 표 7). 2차 매칭 여부는 숙련 파일(`ojp_skill_dedup_{연도}`)에만 있고 이 파일은 `data/`에 없다.
- 숙련 사전에 AI 에이전트 관련 숙련이 있다. `ai_peripheral`의 정의가 "AI 에이전트·아키텍처·API 개발 등 AI 시스템을 구성·연계하는 숙련"(76개)이다.
- 자료 설명은 `data/postings/데이터명세서_연도별최종제공본.docx`에 있다. 받은 파일은 명세서보다 열이 4개 많다(`skills_competency`, `skills_physical`과 그 명칭 열).

### 3.2 숙련코드

- 위계: 대분류(`domain_v4`) → 중분류(`sub_v4`) → 숙련(`skill_code_v4`). 하드 숙련은 대분류 8개, 중분류 40개, 숙련 8,097개이다.
- 직종 숙련 열의 코드는 설명 파일과 100% 일치한다(표본).
- 횡단 숙련 열의 코드 중 약 21%는 설명 파일과 형식이 다른 소프트 코드이다(표본). 모두 의사소통 대분류에 속하고(`SS-01-02-0009` 형태, 표본에서 29종), 숙련명으로 설명 파일의 최종판 코드에 100% 대응된다(`SS-02-0009`).
- 직종 또는 횡단 숙련이 하나라도 있는 공고는 약 52%이다(표본). 결정 10에 따라 나머지는 제외된다.

### 3.3 KED (`data/ked/`)

| 파일 | 내용 | 규모 | 쓰임 |
|---|---|---|---|
| `KED5002.txt` | 기업개요. `\|` 구분, CP949, 48개 항목 | 927만 개 기업 | 설립일, 기업규모 구분, 기업공개 구분, 벤처 여부 |
| `KED5003.txt` | 주요재무정보 | 130만 개 기업 | 쓰지 않음 |
| `KED5016.txt` | 인원현황 | 353만 개 기업 | 쓰지 않음 |

- 2023년 5월 무렵의 자료이며 더 새로운 추출본은 구할 수 없다.
- 사업자번호가 있는 공고 중 KED에 있는 비율은 2021~2023년 90%, 2024년 87%, 2025~2026년 81~82%이다(전체 계산).
- 2025년 결합 공고 기준 결측률은 설립일 8%, 기업규모 구분 13%이다.
- **`KED5002.txt`의 19번째 항목에는 개인사업자의 주민등록번호가 들어 있다. 어떤 스크립트도 이 항목을 읽지 않는다.**

## 5. 두 공간의 경계

- 논문 공간은 `paper/exhibits/`만 읽는다. `experiments/outputs/`를 직접 참조하지 않는다.
- 실험 공간의 `scripts/export_to_paper.py`만 `paper/exhibits/`에 쓴다. 이 스크립트는 지정한 실행 폴더의 표(`.tex`, `.csv`)와 그림(`.pdf`)을 복사하고 `paper/exhibits/MANIFEST.csv`에 한 줄을 추가한다.
- 목록 파일(`MANIFEST.csv`)의 항목: 표·그림 번호, 파일명, 출처 실행 폴더, 코드 시점(git 커밋), 내보낸 날짜, 설명.
- 원고에 쓰는 모든 수치는 `paper/exhibits/`의 파일에서 가져오고, 목록 파일로 출처를 확인할 수 있어야 한다.
- `paper/exhibits/`는 git으로 관리한다.

## 6. 실험 공간

### 6.1 중간 자료

원자료는 수정하지 않는다. 중간 자료는 `experiments/outputs/interim/`에 parquet로 둔다.

| 파일 | 한 행 | 내용 | 만드는 단계 |
|---|---|---|---|

### 6.5 설정과 실행 기록

`config.yaml`의 항목: 분석 기간과 기간 단위, 키워드 사전(엄격, 넓음, 제외), 결과에서 뺄 숙련코드와 인접 숙련 목록, 희소 필터 기준, 직종군 대응표 경로, placebo 숙련 목록, 교차적합 폴드 수, trimming 기준, 난수, LightGBM 설정, 미도입 공고 표본추출 비율.

실행 기록: 추정 스크립트(S5 이후)는 `experiments/outputs/runs/{날짜-시각}_{단계}_{이름}/`에 결과를 쓰고 다음을 함께 남긴다.

- 실행에 쓴 `config.yaml`의 사본
- `run.json`: 코드 시점(git 커밋), 입력 자료의 행 수, 단계별 행 수, 실행 시간, 난수

### 6.6 자료 점검(S0) 보고서

`s00_data_audit.py`는 `proposal.md` 3.2절의 예시 사전을 임시로 써서 다음을 집계하고 `docs/s0-data-audit.md`에 쓴다.

1. 제외 규칙 단계별 공고 수 (연도별)
2. 기간별 처치 공고 수 (엄격한 사전, 넓은 사전, 분기·반기·연 단위)
3. 공고당 숙련 수의 분포와 숙련별 출현율 (희소 필터 기준별 남는 숙련 수)
4. 처치 여부별 사업자번호 보유 비율과 KED 결합 비율
5. 연도별 수집 사이트 구성, 사이트별 처치 공고 비율
6. `ai_peripheral`과 키워드 처치의 겹침
7. 숙련 1개에 대한 결과모형의 학습 시간 (전체 표본, 미도입 공고 표본추출 비율별)

### 6.7 자료 점검 뒤에 정할 사항

`proposal.md` 10장의 항목에 더해 다음을 `docs/decisions.md`에 정해 적는다.

| # | 항목 | 기본값 |
|---|---|---|
| 1 | 사업자번호가 없는 공고의 처리 | 제외 (`proposal.md` 3.5절) |
| 2 | 처치 판별에 제목을 쓸지 | 본문만 사용 (사람인 2025년 이전 제목 결측) |
| 3 | 처치 판별에 AI 에이전트 숙련코드를 함께 쓸지, 결과에서 뺄 코드 | 키워드만 사용, AI 에이전트 숙련코드는 결과에서 제외 |
| 4 | 수집 사이트를 교란변수에 넣을지 | 넣음 |
| 5 | 미도입 공고를 표본추출할지 | 학습 시간 실측 후 결정 |
| 6 | 2차 매칭 숙련의 처리 | 포함 (숙련 파일을 받으면 1차 매칭만으로 재추정) |
| 7 | `dup_count`를 가중치로 쓸지 | 쓰지 않음 |
| 8 | 위계적 다중검정의 1단계 분류 | 중분류 (`sub_v4`) |
| 9 | 2026년 자료의 포함 범위 | 자료 점검에서 월별 건수 확인 후 결정 |
| 10 | 산업 분류 자릿수, IT 직종의 범위 | 자료 점검 후 결정 |

### 6.8 시험

`experiments/tests/`에 pytest 시험을 둔다. 참값을 아는 합성 자료를 만드는 함수를 두고 다음을 확인한다.

- `dml.py`: 숙련별 추정치가 참값을 허용 오차 안에서 복원하는지, 기업 묶음 표준오차, 위계적 다중검정, 기간 간 차이 검정 (`proposal.md` 부록 B의 점검 항목)
- `network.py`: 가중 동시출현 행렬, PMI 변환
- `treatment.py`: 포함 패턴과 제외 패턴
- `confounders.py`: 산업별 처치 비율이 직전 기간 값만 쓰는지
- `skills.py`: 횡단 열 소프트 코드의 최종판 코드 변환, 번들 지표
- `ked.py`: 추출 결과에 주민등록번호 항목이 없는지 (가상 파일 사용)
- `export.py`: 목록 파일에 출처가 기록되는지

시험과 합성 자료에서 나온 수치는 연구 결과로 적지 않는다.

### 6.9 오류 처리

- 입력 파일이나 필요한 열이 없으면 바로 멈추고 무엇이 없는지 알린다.
- 결합 뒤 행 수가 달라지면 멈춘다(공고 기본 자료는 결합 전후 행 수가 같아야 한다).
- 추정 스크립트는 성향점수 점검(`proposal.md` S5의 통과 기준) 결과를 `run.json`에 적고, 통과하지 못한 실행의 결과는 내보내기 스크립트가 거부한다.

## 7. 논문 공간

- `manuscript/`: `main.tex`와 절별 파일(`sections/`). 표와 그림은 `../exhibits/`를 참조한다. 서식은 일반 `article` 문서 양식으로 시작하고 투고처가 정해지면 바꾼다. 조판은 `latexmk`와 XeLaTeX(TeX Live 2025)를 쓴다.
- `references/`: `references.bib`.
- `reviews/`: 원고 검토 기록. 파일명은 날짜로 시작한다.
- `submissions/`: 투고본. 폴더명은 날짜로 시작한다.

## 8. Claude 작업 규칙

| 파일 | 담는 내용 |
|---|---|
| `CLAUDE.md` (최상위) | 연구 개요, 두 공간의 경계, 원자료는 읽기 전용, KED의 주민등록번호 항목을 읽지 않음, 확정 사항은 `docs/decisions.md`에 적은 뒤 `config.yaml`에 반영 |
| `experiments/CLAUDE.md` | 기준값은 `config.yaml`에만 둠. 추정 결과를 보고 하이퍼파라미터를 조정하지 않음. placebo 숙련 목록은 결과를 보기 전에 정함. 교란변수는 같은 기간의 처치 변수로 만들지 않음. 대용량 자료는 필요한 열만 읽음. 합성 자료의 수치는 결과로 적지 않음 |
| `paper/CLAUDE.md` | 수치는 `paper/exhibits/`와 목록 파일에서만 가져옴. 인과 표현은 `proposal.md` 9장의 해석 범위를 따름. 참고문헌은 동료심사 학술지 논문만 씀. 그림은 `paper-figures` 규약을 따름 |

사용자의 전역 용어 원칙(새 용어를 만들지 않음, 은유를 쓰지 않음, 기술 용어는 처음 나올 때 정의)은 두 공간 모두에 적용된다.

## 9. 환경

- Python 3.12, uv로 패키지와 버전을 고정한다(`pyproject.toml`, `uv.lock`).
- 가상환경은 구글 드라이브 밖의 로컬 디스크에 둔다(`UV_PROJECT_ENVIRONMENT`로 위치 지정). 위치는 `README.md`에 적는다.
- 패키지: `numpy`, `pandas`, `pyarrow`, `scipy`, `scikit-learn`, `lightgbm`, `statsmodels`, `doubleml`, `networkx`, `matplotlib`, `pyyaml`, `pytest`, `jupyterlab`.
- `aabundle` 모듈은 편집 가능한 방식으로 설치해 스크립트와 노트북에서 같은 코드를 쓴다.
- git 제외 목록: `data/`, `experiments/outputs/`, 가상환경, 파이썬 임시 파일, LaTeX 조판 부산물, 비밀값 파일.

## 10. 구축 순서
